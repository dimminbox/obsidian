Это по сути аналог GROUP BY в SQL. Любая агрегация начинается со слова aggs, Важно, что при агрегации нужно указать size = 0 чтобы получать только агрегации без документов. Также важно, что перед агргацией нужно выполнять query (перед aggs) иначе агрегация будет идти по всем документам.
Агрегация в ES имеет следующий вид:
{
  "size": 0, // если указать не 0, то ES отдаст также и документы. 
  "aggs": { //блок агрегации
    "by_brand": { //название агрегации
      "terms": { "field": "brand.raw" } //тип агрегации
    }
  }
}

ES поддерживает следующие агрегации:
1. terms - обычная агрегация, которая работает по всем полям, которые доступны в [[Поиск и ранжирование#Сортировка через doc_values]]
2. date_histogram - агрегация по дате
3. avg - агрегация по среднему значению
4. cardinality - агрегация по количеству уникальных значений. ES по умолчанию не берёт все записи для подсчёта уникальных значени, это было бы очень дорого, т.к. пришлось бы загружать все документы в память и лопатить их. Это агрегация работает на внутренней статистике, которая в моменте запроса собирает через алгоритм HyperLogLog. Данные не на 100% точные, обычно погрешность - 1 - 5%, но точность алгоритма можно регулировать точность, за это отвечает параметр - `precision_threshold`.
5. percentiles - процентили, которая показывает, к примеру, что 95% имеет время доставки 7 дней. Процентили можно указать в запросе, например "percents": [10, 50, 90, 99.9]
6. nested - агрегация по nested полю требует совй слой агрегации
7. range - агрегация позволяет получить агрегацию по диапозонам.
   Имеет вид:
   {
	  "size": 0, //обязетально иначе появятся товары
	  "aggs": {
	    "by_price": { //название агрегации, можно указать что угодно
	      "range": { //тип агрегации
	        "field": "PRICES.55.VALUE", //поле
	        "ranges": [ //диапозоны
	          {
	            "to": 0,
	            "from": 200
	          },
	          {
	            "from": 200,
	            "to": 500
	          },
	          {
	            "from": 500
	          }
	        ]
	      }
	    }
	  }
	}
8. вложенные агрегации, которые позволяют агрегировать по агрегированному,например 
   {
	  "aggs": {
		"by_make": {
		  "terms": { "field": "make.raw" },
		  "aggs": {
			"by_model": {
			  "terms": { "field": "model.raw" },
			  "aggs": {
				"avg_price": { "avg": { "field": "price" } }
			  }
			}
		  }
		}
	  }
	}
   
   Агрегация может быть с фильтрацией. Для фильтрации используется отдельная агргация, например
   
  {
  "query": {
    "bool": {
      "must": [
        {
          "nested": {
            "path": "PROPERTIES_SHORT",
            "query": {
              "term": {
                "PROPERTIES_SHORT.CODE.keyword": "MATERIAL"
              }
            }
          }
        }
      ]
    }
  },
  "aggs": {
    "by_material": {
      "nested": { //отдельная агрегация для nested
        "path": "PROPERTIES_SHORT"
      },
      "aggs": { //отдельная агргация для фильтрации
        "filter_material": {
          "filter": {
            "term": {
              "PROPERTIES_SHORT.CODE.keyword": "MATERIAL"
            }
          },
          "aggs": { //итоговая агрегация для значения поля
            "materials": {
              "terms": {
                "field": "PROPERTIES_SHORT.VALUE.keyword",
                "size": 2
              }
            }
          }
        }
      }
    }
  },
  "size": 0
}
