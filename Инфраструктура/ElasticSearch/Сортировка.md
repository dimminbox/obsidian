  
##### Сортировка через doc_values

Сортировать можно не только по score, но и по всем полям, которые попадают в doc_values (это numeric, bool, keyword, date). Для text doc_values не строится поэтому по ним нельзя отсортировать напрямую, для этого используется multi field. 
Keyword в свою очередь сортируется лексиграфически (общий Unicode порядок). 

Для пагинации существуют size, from. Но эта операция дорогая, т.к. каждый шард сам собирает size + from, потом они объединяются и затем координатором берутся уже итоговые size, from. На всё это тратится и CPU и память. Чем больше from тем больше множество документов, которые берутся каждой шардой.

Эту проблему частично закрывает механизм search_after. НАпример, 
{
  "size": 10,
  "sort": [
    { "price": "asc" },
    { "_id": "asc" }
  ],
  "search_after": [1500, "abc123"],
  "query": { "match": { "title": "тормозные колодки" } }
}
 В этом случае каждый шард уже отдаёт 10 подходящих документов, координатор работает только с теми документами, которые удовлетворяют фильтру, ему не нужно отсекать кучу документов с from.
 
 Здесь ES возвращет 10 документов, у которых price > 1500 и _id > "abc123", т.е. это не даёт классической пагинации (мы не можем сразу перейти к n странице), но используется в автозагрузке документов.
 
 Ранее также использовался scroll api, который также использовался для пагинации. По сути это паганация в памяти ES. При поиске мы добавляем к запросу ?scroll=1m и он вернёт ID скрола, который живёт 1 минуту как в этом примере, если его не использовать. В новых версиях это запрещено т.к. очень сильно нагружает ES.

###### Сортирвка через fielddata

Это сортировка по полю с форматом text. Text не хранится в структуре doc_values поэтому не может быть отсортирован через неё. Но иногда всё таки нужно отсортирвать по text и на помощь приходит fielddata. Это очень дорогая операция, которая выгружает структуту из индекса терм - документ , переворачивает её и сортирует документы по полю применяя разные алгоритмы сортировки. При этом структура висит в памяти и, как правило, весит много.
