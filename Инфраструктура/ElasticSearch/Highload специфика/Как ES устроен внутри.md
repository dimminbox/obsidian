ES хранит документы на диске, также он собирает индексы term dictionary (список термов), postings_list (связь термов с номерами докуентов) и структуры doc_values для точного поиска и агрегации. В процессе работы эти структуры кешируются средствами ОС и отчасти находятся в памяти.

##### Шардирование и реплицирование

Индекс можно разбить на шарды, т.е. на части. Каждую шарду должен обрабатывать либо отдельный сервер либо отдельного ядро процессора поэтому шардирование делают не только в кластере но также и на многоядерном процессоре. Шарды имеют смылс когда индекс большой (от 20 Гб) так как привносят нагрузку на ES для координации между ними.

Для обеспечения отказоустойчковсти используется реплицирование, т.е. если одна реплика будет не доступна, другая подхватит запросы. Кроме этого они используются для распределения нагрузки при чтении.

Кластёр ES состоит из нод, роли которых могут быть:
- master node - управление кластером
- data node - хранение данных, выполнение запросов
- coordination node - нода координатор, которая занимается маршрутизацией запросов
##### Кеширование

Для обспечиния быстрого чтения ES также исползуется различные кеши:
 - Query cache - кеширует список id документов, которые были получены через filter.
 - Request Cache - кеширует весь ответ целиком, повторный запрос приводит к тому, что ES берёт ответ из кеша. Это происходит если кеш не  обновлился. Добавление нового документа сбрасывает кеш
 - Field data cache - кеширует значения полей для сортировки / агрегации, лучше использвоать doc_values

При добавлении документа докуент не сразу становится виден для поиска, но как только это происходит кеши инвалидируются. Поэтому нужно не использовать refresh_interval который задаёт задержку. ES хранит документы в сегментах на диске. При поиске он ищет документы в разных сегментах. При добавлении документ сначала попадет память а дальше в сегмент. Эту задержку и определяет refresh_interval. Иногда используется force_merge для объединения всех сегментов в один, это хорошо для чтения, поэтому это делают перед операциями, которые критичны для чтения (архивирование, копирование индекса).

###### Алиасы

Если необходимо поменять индекс без даунтайма, то используют механизм POST _reindex, который копирует данные из старого индекса в новый:

1. Создаём новый индекс с нужным количеством шард
2. Создаём алиас с products_v1 на products
3. Копируем данные из старого индекса в новый через POST _reindex
4. Использууем alias для переключения индексов _POST aliases
   POST _aliases
	{
	  "actions": [
	    {"remove": {"index": "products_v1", "alias": "products"}},
	    {"add": {"index": "products_v2", "alias": "products"}}
	  ]
	}
	
	Он удаляет старый алиас и создаёт новый
	Если не использовать алиасы, то такой возможности не будет

ES предоставляет /index/_mget, который позволяет поулчить доки по их id через batch. РАботает быстро т.к. не рассчитывает score, не анализирует запрос, сложность O(1) для каждого документа.
