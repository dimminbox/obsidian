При поиске используется система сигналов, например, есть такой  раздел - добавляем 

Сигналы:
  - Точный код/штрихкод/артикул — 20000
  - Раздел (точное совпадение) — 10000
  - Бренд (по полю ТМ.TOKEN) — 10000
  - Синонимы — 10000
  - Автодополнение кода — 5000
  - Совпадение с названием (полное) — 5000
  - Уникальное свойство (KEY) — 5000
  - Частичное совпадение кода/артикула — 2500
  - Совпадение с названием (частичное) — 2500
  - Раздел 4-го уровня — 2500
  - Конкретный товар (по заголовку) — 1000
  - Теги (атрибут+значение) — 1000
  - Серия — 750
  - Производитель / страна / раздел 1-3 уровня — 500
  - Обычное свойство — 100

Все товары сначала просеиваются через SEARCH.SEARCH и это даёт хоть какую - то гарантию, что в поиск не попадёт всякий мусор, т.к. в этом поле собрана вся информация о товаре. Абсолютно все сигналы будут просеяны через SEARCH.SEARCH.

Если на предыдущих этапах найдены конкретные разделы, то поиск сужается только до товаров, которые в них.
  
Если были найдены бренды/серии, то они сужают поиск через should

Если поиск не сужен, то идёт поиск по тем же полям бренд/серия/раздел

Если ранее были найдены товары по title, то это тоже отдельный сигнал.
