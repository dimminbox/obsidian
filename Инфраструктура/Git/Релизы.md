#### git tag

Релизы часто помечают тегами, которые могут быть лёгкими и аннотированными. Первые просто указывают на коммит, во втором случае физически создаётся новый объект тег.  Аннотированные теги включают своим описание, дату, автора, который указывает на определённый коммит.  Также их можно подписать с помощью ключа, обычные - нет. Теги в отличие от веток не двигают.

Команда `git tag -a v1.4.0 -m "Release 1.4.0" a1b2c3d  создаёт тег на указанном коммите. 

На сервер теги отправляются с помощью команды - `git push origin v1.4.0`.
Также можно отправить на сервер новые коммиты и все аннотированные теги, которые к ним относятся и которых нет на сервер - `git push --follow-tags`

Для получения всех тегов можно использовать команду `git tag --sort=v:refname`, которая покажет все теги отсортированные по semver правилам (major, minor, patch, alphan, beta, rc). Команда `git tag --sort=-v:refname` - отдаст теги в обратном порядке.

#### git describe

Команда нужна для того чтобы показать на каком теге сейчас идёт работа. Она выводит последний тег даже если существуют коммиты, которые ушли вперёд него. Ответ приходит в виде `v2-1-gb42e237` где v2 - тег, 1 - количество коммитов после него, b42e237 - последний коммит.

#### Содержимое релиза

Для того чтобы посмотреть что войдёт в релиз нужно понять что есть в текущем коммите, помеченном тегом и основной веткой. Для этого команда - `git log v1.4.0..origin/main --oneline --first-parent`

--oneline - одна строка на коммит
--first-parent - показывает только MR без входящих туда коммитов, результат годится для release notes

Также можно посмотреть чего не хватает в релизе, т.е. сравнить main  и текущий релиз -
`git cherry -v release/1.4 main`. Эта команда показывает обычные изменения а также изменения, сделанные через cherry-pick.

#### Откат релиза

Если после релиза нужно откатить какой - то коммит, то делают [[Откаты#git revert]] нужного коммита, который создаёт новый коммит "Revert" с указанным тектом - пояснением отката.
