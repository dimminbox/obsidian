#### git status

git status -sb (-s короткий вывод, -b добавляет ветку) даёт информацию о локальных изменениях, которые не закоммичены, например:

main...origin/main [ahead 2, behind 1] //два коммита которых нет на сервере и один , которого нет локально (разница между @{u}..HEAD)
 M src/app.cs //файл изменён, изменения не добавлены в индекс
M  src/db.cs //файл изменён и добавлен
MM src/api.cs //добавлен, но потом изменён ещё раз
A  src/new.cs //новый файл
?? notes.txt //не отслеживает

#### git log
Показывает информацию по коммитам, изменениям, общую картину в различном виде, например, 

git log --oneline --graph --decorate --all
 - --graph - строит граф, 
 - --oneline - всё в одной линии, 
 - --decorate - показывает ветки и теги, 
 - --all - все ветки
 - --stat показывает какие файлы изменены и сколько изменений
 - -p полный diff каждого коммита
 - у команды есть фильтры (по автору, сообщению, по файлу, за период), например, -5 - последние 5 коммитов

##### git diff

Показывает разницу между коммитами, локальным состоянием и закомиченным. Например, git diff показывает что не было добавлено, git diff --staged то, что попадёт в следующий коммит.

#### git show

Показывает изменения целиком без git checkout. Удобно смотреть чужие изменения.
Например, git show <название ветки> чтобы посмотреть что изменилось на чужой ветке в последнем коммите, флаг --stat показывает только названия файлов. 
git show master:test/test.cs - показывает содержимое файла в ветке master

#### git blame 

Показывает автора изменений на любом коммите любого файла, например,  git blame da461ec main.cs показывает изменения в файле main.cs на коммите с hash равным da461ec
