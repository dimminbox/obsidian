#### git add/restore
Иногда бывает, что изменений слишком много и нужно закомитить изменения в файле по частям. Для этого нужна команда git add - p которая предлагает варианты как закомитить, можно выбрать для коммита только конкретные изменения.

git restore -p сбрасывает изменения из индекса, затирает локальные изменения
git reset --soft имя_ветки сбрасывает все коммиты из ветки, которые отличаются от указанной ветки, изменения буду в индексе и для того чтобы они попали одним коммитом в текущую ветку нужно просто сделать git commit
#### git commit

git commit -v добавляет в редактор для сообщения всю информацию, которая коммитится.

#### git commit --amend

git commit --amend добавляет в последний коммит новые изменения в индексе, добавленные через git add. Используется, когда закоммитили не все изменения но только в случае если их не отправили на сервер.

#### git commit --fixup

git commit --fixup=hash, где hash - это хэш коммита. Команда для того чтобы внести изменения в необходимый коммит. Но по факту старый коммит не изменяется (это архитектурно невозможно), добавляет новый коммит с приставкой fixup!

Затем можно склеить коммит fixup! к предидущему коммиту. В этом случае можно использовать команду 
git rebase -i --autosquash hash, где hash - это коммит который распологается перед коммитом fixup! и предидущим. То есть мы тем самым показывает механизму rebase оба коммита а он склеивает fixup к предыдущему. При этом перестраиваются все коммиты после указанного, т.е. они получают другие хэши.
