
Иногда нужно взять один или несколько коммитов на одной ветке и влить в другую, например при сборке релиза. Для выбора коммитов есть команда git cherry-pick. 

На конкретной ветке мы можем сделать git cherry-pick -x hash1/hash1^..hash2
где hash1 - хэш коммита, hash1-hash2 - диапозон коммитов. 
-x - дописывает в коммит сообщение текст "(cherry picked from commit a1b2c3d…)"

Если возник конфликт его нужно разрешить и далее выполнить либо git cherry-pick --continue либо git cherry-pick --abort.
Сама команда создаёт новый коммит, который является комией выбранного.

#### git cherry
После переноса можно посмотреть какие cherry коммиты были перенесены в рамках cherry-pick, используя git cherry -v release/1.4 main, например:

\- 1111111 Fix null reference      ← копия уже в release/1.4
\+ 2222222 Fix rounding bug        ← не перенесён
\+ 3333333 Add logging             ← не перенесён

Так как хэши у коммитов разные, то необходимо понимать, что один коммит есть комия другого. Для этого Git использует patch-id, который вычисляется для коммитов на лету и измениясовпадает т.к. изменения одинаковые.
