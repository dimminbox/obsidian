
#### Обыкновенное скачивание

Для того, чтобы скачать изменения с сервера и не вливать в локальные ветки существует команда git fetch. Она просто скачивает содержимое в orig ветки, которые находятся локально. Для того чтобы скачать и залить изменения - git pull. Для клонирования репозитория используется git clone.

#### Скачивание части репозитория

Бывает так, что репозиторий огромный и необходимо скачать только небольшую его часть. 
Команда `git clone --filter=blob:none --sparse <url>` скачивает структуру и кладёт её в .git, в рабочей папке будет пусто.  Далее для того, чтобы файлы появились в структуре нужно сделать `git sparse-checkout set --cone services/api`, которая скачивает файлы указанной папки но делает их пустыми. Само же содержимое скачивается только при открытии файла или checkout, diff операциях.

#### Скачивание нескольких коммитов

Как правило, CI скачивает всю ветку целиком, а это множество коммитов хотя по сути ей нужен только последний или несколько для того чтобы провести некоторые проверки. Для того, чтобы скачать последние N коммитов можно воспользоваться командой - git clone --depth 1 url, где depth 1 - это указание количество скачиваемых коммитов.

#### Ускорение работы репозитория

Иногда репозиторий настолько большой, что команды типа git status, git log тормозят. 
Во - первых можно посмотреть сколько объектов в репозитории и сколько он занимает с помощью команды - `git count-objects -vH`.

Затем можно ускорить работу репозитория с помощью `git maintenance start` который включает фоновое обновление служебных файлов (локальная бд), бинарный кэш графа коммитов и прочие. Сам граф коммитов можно обновить через `git commit-graph write --reachable` или вообще включить такое обновление после каждого fetch.

Также фоновые опрос изменённых файлов можно сделать через механизм fsmonitor командой `git config core.fsmonitor true` которая будет с помощью ОС узнавать об изменённых файлах поэтому git status будет работать в разы быстрее.

Иногда нужно хранить бинарные файлы в репозитории, GIT по - умолчанию плохо их жмёт, более того новое изменение - по сути новый файл. Если файл большой, то при каждом изменении файла в репозиторий будет записан бинарный файл заново что будет расходовать дисковое пространство. Решение - это использовать Git LFS (Git Large File System) которая заключается в том, что в git лежат только ссылки на файлы а сами файлы хранятся на отдельном LFS сервере.

#### Вложенный репозиторий

Иногда нужно к репозиторию подключить другой репозиторий, например, какой - то компонент или библиотеку. Это можно сделать с помощью создания ссылки на него командой - `git submodule add <url> libs/common` либо просто влить его с помощью `git subtree add --prefix=libs/common <url> main --squash`. В последнем случае код становится частью основного репозитория.
