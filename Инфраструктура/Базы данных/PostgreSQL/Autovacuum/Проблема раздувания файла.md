После того как мёртвые строки были помечены соотвествующим образом бывает ситуация когда в процессе VACUUM новые строки не успевают встать на место старых и от этого файл физически раздувается. Эти мёртвые строки разбросаны по всему файлу и поэтому нужно собрать новый файл, в котором их не будет иначе файл для ОС будет раздуваться всё больше и больше. Эту задачу можно решить с помощью расширения `pg_repack` и мехаизма VACUUM FULL.

`pg_repack` выполняет сборку нового файла в фоне, накапливая инкрементные изменения, которые возникают в процессе сборки нового файла с первоначальным чтобы потом их накатить на новый файл. Во время переноса первончальная таблица почти не блокируется, блокировка работает когда идёт подмена файла.

`VACUUM` FULL переносит данные в новый файл и берёт ACCESS EXCLUSIVE блокировку поэтому `VACUUM`я продакшене он не используется.

Мониторить bloat (раздувания) файла можно с помощью:
- `n_dead_tup`, `last_autovacuum` в таблице `pg_stat_user_tables`
  
	SELECT relname, n_live_tup, n_dead_tup,
	       round(100.0 * n_dead_tup / nullif(n_live_tup + n_dead_tup, 0), 1) AS dead_pct,
	       last_autovacuum, autovacuum_count
	FROM pg_stat_user_tables
	ORDER BY n_dead_tup DESC LIMIT 10;
	
	n_live_tup   -  примерное количество живых строк
	n_dead_tup - примерное число мёртвых строк

- старые транзакции в pg_stat_activity. Неактивный слот (active = false) с очень старым restart_lsn или xmin забыт и держит и WAL, и мёртвые строки.
  
	SELECT pid, state, xact_start, now() - xact_start AS age, query //долгие транзакции
	FROM pg_stat_activity
	WHERE xact_start IS NOT NULL
	ORDER BY xact_start LIMIT 10;

- старые слоты репликации
  
	  SELECT slot_name, active, xmin, catalog_xmin, restart_lsn
	FROM pg_replication_slots;

- подвисшие prepared transactions
  
  SELECT gid, prepared, now() - prepared AS age FROM pg_prepared_xacts;
