
Вставлять данные в таблицу можно разными способами. Используя [[UPSERT]] при каждой вставке идёт планирование запроса, тратится время на сетевой обмен, идёт обращение к диску для записи в WAL - хранилище. Это достаточно медленно. Для быстрой вставки данных используются другие механизмы

###### Copy

Это потоковое копирование данных из внешнего источника в таблицу с записью в WAL через буффер (1000 строк). Работает очень быстро, поддерживает тригеры, ограничения (NOT NULL, UNIQUE, PRIMARY KEY и т.д.) но не имеет логики для обработки ошибок как ON CONFLICT. При возникновении хотя бы одной ошибки падает весь процесс.
Работает это следующий образом. Клиент шлёт данные в stdin либо в формате Binary (где размер каждого поля заранее определён) либо шлёт в csv (разлелить - запятая). Сервер (backend) с помощью команды COPY их читает, например,

COPY items (id, name, price) FROM STDIN WITH (FORMAT binary); 
Причём STDIN на каждый такой импорт свой.

В C# COPY поддерживает NpgsqlBinaryImporter.
###### Батчинг

Заключается в том, что отправляется множество VALUES в INSERT. Но есть ограничение по отравке данных в одном INSERT. Это 65535 параметров, то есть в таблице с 5 столбцами будет 13 тысяч в запросе. Можно сделать процесс идемпотентным, добавив ON CONFLICT DO NOTHING либо каждый раз стартовать, учитывая последний обработанный батч. Каждый батч идёт в своей транзакции, то есть один раз происходит планирование запроса, один коммит и один fsync с wall.
