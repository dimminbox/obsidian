- Nested Loop. Для внешней таблицы получаем строки каким угодно способом (индекс, полное сканирование). Далее осуществляется поиск для каждой найденной строки из внешней таблицы строки из внутренней таблицы. Внешнюю таблицы проходим один раз а вот внутреннюю количество раз равное количеству найденных строк во внешней таблице. И здесь важно наличие индекса во внутренней таблице ведь если его нет, то для каждого значения из внешней нам необходимо читать всю внутреннюю таблицу
  
- Hash join строит хэш таблицу (ключ - значения поля, значение  - строки) из меньшей и помещает её в work_mem. Затем проходит по большой таблице (либо с помощью индексов либо с seq scan) и далее находит совпадения с хэш-таблицей за O(1). Этот метод не требует индексов, но требует загрузки хэш таблицы в work_mem. Если work_mem не хватает, то приходится часть хранить на диске и поочерёдно загружать в work_mem что существенно замедляет процесс. Работает только с операцией "=".
  
- Merge join работает когда на обеих таблицы есть отсортированные данные. Работает в два потока где каждый читаем свои данные, если произошло совпадение, то запоминаем строку.
