
Дедлоки возникаются, когда две транзакции ждут друг друга, например, когда в первой транзации идёт обновление по ID = 1, ID = 2 а во второй транзации обновление по ID =2 , ID = 1. Таким образом первая не может закончится потому что не можем обновить ID = 2 т.к. её удерживает вторая, а вторая не может закончится т.к. не может обновить ID = 1 т.к. её обновляет первая.

На практике такое возникает когда транзакции слишком долгие или разный порядок изменения строк (как выше) или транзакция ждёт по FK дочерюю таблицу, в которой в этот момент, например,  идёт INSERT.

Предотвратить их можно изменив транзации, применив ретрай логику. 

Сам Postgres имеет механизм отслеживания транзакций, который принудительно просто завершает одну из них.
