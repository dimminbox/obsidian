Postgres  - это реляционная БД, которая состоит из нескольких процессов:

###### Postmaster

Он слушает порт и запускает другие процессы если нужно

##### Backend 

Это процесс, который непосредственно работает с данными. Под каждое соединение от клиента postmaster запускает свой новый процесс backend (это дорого). Процесс загружает данные из диска в память (shared_buffers) и работает с данными исключетельно в памяти. Данные называются чистыми если в памяти они совпадают с данными на диске, если их изменили, то они называются грязными данными.

Перед записью данных в памяти происходит их запись в wal_buffers, это специальная структура, которая хранит всю историю изменений.  

Далее backend изменяет непосредственно сами данные в shared_buffer.

Далее backend скидывает историю изменений на диск из wal_buffers. Но чтобы облегчить ему процесс также работает WAL writer, который пишет их каждые 200 мс по умолчанию, то есть backend не всегда нужно сбрасывать все изменения в журнал т.к. часть работы за него сделал WAL writer.

То есть транзакция считается законченной когда добавась запись об истории измененийв  в WAL журнале а не изменились сами данные на диске.

Иногда backend может сам сбросить данные из shared_buffers на диск если место в shared_buffers закончилось, но это происходит редко. Гораздо чаще данные из памяти сбрасывают другие процессы.

Кроме записи данных от также занимается их отбором. Backend потребляет память для операций GROUP BY, ORDER BY, DISTINCT, HASH JOIN. Для выполнения каждой такой операции из списка используется буфер work_mem.

Для выполнения операции WHERE буфер не требуется, он просто читает данные из shared_buffers и фильтрует их.
###### MVCC

Для чтения данных (в том числе WHERE) backend не опирается на блокировки между читателями и писателями, он использует механизм MVCC (Multi-Version Concurrency Control) - механизм многоверсионного управления конкурентным доступом к данным, который решает какую версию строки показать читателю основываясь на xmin, xmax строки и сравнивая эти показатели со снимком читающей транзакции.
###### Checkpointer

Это процесс, который скидывает грязные страницы на диск из shared buffers по расписанию каждый `checkpoint_timeout` (обычно 5 минут).
###### Background writer 

Это процесс, которые скидывает грязные страницы из shared_buffer на диск но маленькими порциями. постоянно, зглаживая нагрузку для checkpointer.
