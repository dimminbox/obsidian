Мы не можем использовать обычный b-tree индекс для JSON значений т.к. сам b-tree хранить весь json как значение целиком и поэтому по его части нельзя осуществить поиск. На помощь приходит специальный тип индекса - Generalized Inverted Index используется для хранения объектов, которые состоят из значений, например, JSON, элементы массива, тест, т.е. любые многоэлементные значения. Для JSON он хранит значения ключей json, который ссылаются на строки таблицы.

CREATE INDEX idx_orders_data_path ON orders USING GIN (data jsonb_path_ops);

jsonb_path_ops обозначает, что в индексе будут хранится хэши значений, который есть в data. Например, если в data есть {"status": "paid"}, то в индекс запишется hash(status, paid), который будет указывать на TID. Таким образом в GIN индекс попадут все поля со всеми значениями одного документа и TID будут указывать на этот документ. Он поддерживает только @> операции (поиск по значениям). Поэтому чем больше полей в документе, тем дороже обновлять GIN индекс.

jsonb_ops пишет в индекс только ключи и значения с указанием на TID, то есть буквально всё, что есть в json попадёт в индекс и будет указывать на TID. Используется в запросах, которые находят документы у которых вообще существует поле, не подходят для запросов `@>`. 

GIN всё равно обратится к таблице потому что он не поддерживает index only scan, include.

B-tree тоже поддерживает JSONB, например:
CREATE INDEX idx_orders_status ON orders ((data->>'status'));
но в индекс попадут лишь те поля, которые мы укажем.
