Бывают ситуации когда необходимо сделать запрос по определённому столбцу, который монотонно увеличивается в очень большой таблице. ТАким столбцом может быть created_at. Чтобы сделать поиск быстрее применяются BRIN (Block Range Index) индексы.

Основная идея: таблица физически делится на фиксированные диапозоны физических страниц не по значениям а просто по порядку их хранения. Для каждого такого диапозона BRIN запоминает min/max по необходимому полю.

Когда происходит запрос BRIN находит номер диапозона а затем по формуле рассчитывает диапозон страниц где могут лежать эти значения по формуле - `range_id × pages_per_range` где range_id - это номер диапозона. 

Но это работает только в том случае если данные в колонке монотонно возрастают и не изменются случайный образом иначе.
