Postgres  - это реляционная БД, которая состоит из нескольких процессов:

###### Postmaster

Он слушает порт и запускает другие процессы если нужно

Сами данные таблиц и индексов хранятся на диске в специальных сегментах (максимум 1Гб). Если таблица или индекс больше 1Гб, то создаётся второй и последующие сегменты. Единица чтения в postgres  - это страница, (8 Кб).
##### Backend 

Это процесс, который непосредственно работает с данными. Под каждое соединение от клиента postmaster запускает свой новый процесс backend (это дорого). Процесс загружает данные из диска в память (shared_buffers) и работает с данными исключетельно в памяти. Данные называются читыми если в памяти они совпадают с данными на диске, если их изменили, то они называются грязными данными.

Перед записью данных в памяти происходит их запись в wal_buffers, это специальная структура, которая хранит всю историю изменений.  

Далее backend изменяет непосредственно сами данные в shared_buffer.

Далее backend скидывает историю изменений на диск из wal_buffers. Но чтобы облегчить ему процесс также работает WAL writer, который пишет их каждые 200 мс по умолчанию, то есть backend не всегда нужно сбрасывать все изменения в журнал т.к. часть работы за него сделал WAL writer.

То есть транзакция считается законченной когда добавась запись об истории измененийв  в WAL журнале а не изменились сами данные на диске.

Иногда backend может сам сбросить данные из shared_buffers на диск если место в shared_buffers закончилось, но это происходит редко. Гораздо чаще данные из памяти сбрасывают другие процессы.
