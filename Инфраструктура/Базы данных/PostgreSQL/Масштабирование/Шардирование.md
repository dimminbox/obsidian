Необходимо для масштабирования записи и распределения больших данных из таблиц. Идея в том, что таблица разбивается на шарды, которые хранятся на разных серверах. Нативной поддержки шардирования в Postgres нет, поэтому оно реализуется следующими способами:
- расширение Citus, которое ставится в Postgres, понимает какую шарду использовать при запросе и перенапрвляет запрос на нужный сервер с нужной шардой.
  
  CREATE EXTENSION citus; -- подключаем рабочие серверы (в них будут лежать шарды) SELECT citus_add_node('worker-1', 5432); 
  SELECT citus_add_node('worker-2', 5432); -- таблица обычная, затем говорим: шардируй по user_id 
  CREATE TABLE orders ( id bigint, user_id bigint, amount numeric, PRIMARY KEY (user_id, id) ); SELECT create_distributed_table('orders', 'user_id');
  
  Если ключа нет, то Citus будет отправлять данные на все шарды, собирать ответи и джойнить их
- приложение - клиент само решает на какой сервер стучаться в зависимоти от ключа шарды и его значения, например, (int)(Math.Abs(userId) % shards.Length) - где userId - ключ шардирования
- прокси для шардирования, например, PgCat

Ключ шардирвоания должен быть в каждом запросе, также он должен распараллеливать данные равномерно иначе получатся горячие шарды.

Шардинг имеет цену - он тяжёлый, joins между шардами сложны, нужны реплики для каждой из шард.
