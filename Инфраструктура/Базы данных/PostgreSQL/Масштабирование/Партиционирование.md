Основная идея партиционирования - это обеспечить чтение данных в зависимости от условия только из одной партиции, то есть не перебирать все данные таблицы. Это увеличивает скорость. Кроме этого их использование помогает управлять данными, т.к. данные определённого вида хранятся в одной партиции. Партиции лежат на одном сервере, но могут лежать на разных дисках.

На основании запроса (в запросе должен быть ключ партиции) планировщик выбирает  необходимые партиции, этот процесс называется prunning (обрезка).

В планировщике можно увидеть следующие этапы: 
- Gather (сборка если чтение партиций параллельное)
- Append (сборка данных последовательно)

Если в запросе нет ключа партиции, то читаются все, запрос становится медленнее т.к. помимо чтения всех партиций нужно ещё сделать append и sort.

Партиционирование может быть следующих типов:

 - по списку значений
   CREATE TABLE orders (...) PARTITION BY LIST (region);
   CREATE TABLE orders_eu PARTITION OF orders FOR VALUES IN ('DE', 'FR', 'IT'); 
   CREATE TABLE orders_ru PARTITION OF orders FOR VALUES IN ('RU', 'BY', 'KZ');
   CREATE TABLE orders_rest PARTITION OF orders DEFAULT; - всё остальное
   
 - по диапозону значений какого - то поля (как правило по дате), границы партиции пользователь создаёт сам
   
   CREATE TABLE shipment (id bigint, ...) PARTITION BY RANGE (id);
   CREATE TABLE shipment_1 PARTITION OF shipment FOR VALUES FROM (1) TO (1000000); CREATE TABLE shipment_2 PARTITION OF shipment FOR VALUES FROM (1000000) TO (2000000);
   CREATE TABLE shipment_3 PARTITION OF shipment DEFAULT; - всё остальное
   
 - по хэшу. От ключа партиции считается HASH(key) и берётся остаток деления на 4, если партиций 4.
   CREATE TABLE users (id bigint, name text) PARTITION BY HASH (id);
   CREATE TABLE users_0 PARTITION OF users FOR VALUES WITH (MODULUS 4, REMAINDER 0);
   CREATE TABLE users_1 PARTITION OF users FOR VALUES WITH (MODULUS 4, REMAINDER 1);
   CREATE TABLE users_2 PARTITION OF users FOR VALUES WITH (MODULUS 4, REMAINDER 2);
   CREATE TABLE users_3 PARTITION OF users FOR VALUES WITH (MODULUS 4, REMAINDER 3);
   
   Мы получаем равномерное распределение по ключу, но количество партиций нужно задавать заранее, для их изменения нужно пересоздавать партиции. Также мы не можем удалить все старые данные т.к. они перемешаны по партициям.
   
Первичные и уникальные ключи должны включать клю партиции.

В каждой партции живут свои индексы, которые могут быть использованы при запросе. В процессе выполнения запроса происходит склейка данных (append) и дальнейшая сортировка  когда, например, данные не были отсортированы в индексе и их нужно отсортирвоать по другому полю (которое не в индексе).

Партиции живут на диске как будто бы это отдельные таблицы со своим visibility map и FSM, autovacuum работает по каждой из них отдельно. Партиции можно вынести в отдельный tablespace, например, архивные данные вынести на медленный диск.

CREATE TABLESPACE cheap_hdd LOCATION '/mnt/hdd/pgdata';
CREATE TABLE shipment_2023_01 PARTITION OF shipment FOR VALUES FROM ('2023-01-01') TO ('2023-02-01') TABLESPACE cheap_hdd;
