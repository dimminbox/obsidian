Git - инструмент для хранения и контроля за версиями файлов и папок, необходим для того, чтобы хранить историю изменений. Основная идея git - это использование хэшей. А именно каждый объект хранится в git с сжатом виде в соответствующей папке.

Git хранит объеты четырёх типов - blob (файл), tree (директория), commit, метка на коммит (tag)
###### Тип blob

Каждый файл хранится как blob - объект и лежит под именем - хэш, который считается от типа, длины и содержимого файла . Два одинаковых файла (побайтово) будут сохранены в git как один blob, но в tree будут две ссылки с разными именами но один хэшем. Название файла не хранится в blob.
##### Тип tree

Каждая директория хранится как tree - объект и лежит под именем - хэшем, который также считается от строки tree<длина>\0<записи>, где длина - размер всех записей в байтах, записи - содержимое, которое содержит перечень строк, описывающих каждый из вложенных объектов, например через команду: 

git cat-file -p 2cfae6d64b7910257e5169bc6dde3ffb49d6245f, где - 2cfae6d64b7910257e5169bc6dde3ffb49d6245f - это хэш 
 
100644 blob c1c33ccdacbcce81afa8f4ff611586d8d1d9ae1c	main.cs
040000 tree 2cccb2a792f1089d325ff8c67252bafbf6d14ea5	test

где 100644 - атрибут (100644 - обычный файл, 100755 - исполняемый, 120000 - символическая ссылка, 160000 - ссылка на коммит с другом репозитории, 040000 - папка)

Физически эти объекты хранятся в файлах c1/c33ccdacbcce81afa8f4ff611586d8d1d9ae1c и 2с/ccb2a792f1089d325ff8c67252bafbf6d14ea5 соответственно в сжатом виде с помощью Zlib.

Корневая директория хранит ссылки на вложенные файлы и папки первого уровня. 
Причём, названия файлов сохранены в tree а не в blob чтобы при переименовании не создавать новых blob, т.к. в этом случае имя хранилось бы в содержимом файла blob.
##### Тип commit
Коммит хранит только корневую дирректорию помимо собственных атрибутов.  Хэш последнего коммита можно посмотреть командой - git rev-parse HEAD.

Например:

dimm@linux:~/projects/git/.git/objects$ git cat-file -p 

81a29a92176be2a7f68e731d3bb9f4b180a42192 - хэш коммита
tree 2cfae6d64b7910257e5169bc6dde3ffb49d6245f - хэш корневой дирректории
author loginov.dn <loginovdn.it@relef.ru> 1792523626 +0300 - автор и время в UNIX формате
committer loginov.dn <loginovdn.it@relef.ru> 1792523626 +0300 - тот, кто создал коммит
init - сообщение

##### Тип tag

Это объект, который ссылается на другой объект, который может быть чем угодно. Можно посмотреть командой - git cat-file -p v1. Такие объекты нужны для удобства наименования, например, можно перейти на коммит по его тегу, посмотреть разницу между тегами, CI часто срабатывает на появление нового тега.

object 81a29a92176be2a7f68e731d3bb9f4b180a42192 - хэш объекта, на который указывает тег
type commit - тип объекта, на который ссылается
tag v1 - сам тег
tagger loginov.dn <loginovdn.it@relef.ru> 1792526895 +0300 - имя того, кто проставил тег
первый релиз - сообщение

Физически теги хранятся в папке .git/refs/tags
