#### git stash

Прячет изменения чтобы рабочая ветка была чистой. Команда git stash прячет изменения и создаёт объект в reflog с ними локально. git stash pop - накатывает изменения из объекта а сам объект из reflog уничтожается. Также можно создать веткку из stash, например, git stash branch fix-auth stash@{0}, где fix-auth - имя ветки, stash@{0} - объект в reflog

#### git worktree

Работае с рабочими ветками, т.е. одновременно может быть сразу несколько рабочих веток.Бывает так, что нужно срочно сделать фикс в другой ветке не исопльзуя команду stash на текущей. Для этого есть команда, например, 
git worktree add -b hotfix/PAY-1 ../hotfix origin/main

Она создаёт в папке ../hotfix ветку hotfix/PAY-1 из ветки origin/main и там мы вольные делать что хотим. После того как всё сделали мы можем удалить временную папку - git worktree remove ../hotfix и переключить на прежнюю ветку в том же состоянии в котором она было до перехода на ветку hotfix/PAY-1.

#### git switch

Только переключается между ветками, ничего больше в том время как git checkout может заменять локальный файл файлом из индекса и другое.

#### git fetch --prune

Скачивает ветки с orgin и удаляет все локальные ветки, которых нет на сервере в origin

#### git fetch

Просто скачивает изменения и обновляет origin/main.
#### git pull

Подтягивает коммиты с origin и актуализирует локальную ветку. 

git pull --ff-only стягивает изменения с origin  в локальные только если не нужно делать merge. Если ветки разошлись, git выдаст ошибку.

git pull --rebase - если ветки разошлись, то локальные коммиты будут перезаписы поверх коммитов с сервера и локальные коммиты получает новые хэши.

#### git branch
git branch --merged main показывает ветки, чьи коммиты уже влиты в ветку main.
git branch -vv показывает все ветки и помечает локальные ветки как "gone" если origin ля них удалены с сервера, для актуализации origin веток на локале нужно использовать git fetch --prune
