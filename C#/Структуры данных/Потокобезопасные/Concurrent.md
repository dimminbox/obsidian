
ConcurrentBag <T> - это по сути мешок, который не гарантирует порядок при выборе объектов. Создаёт локальный список для каждого потока.

ConcurrentQueue<T>, ConcurrentStack<T> использует Interlocked для удаления и добавления без блокировок. 

Не реализует механизм back pressure. Backpressure - механизм, который замедляемт продюсеры если консамеры не успевают обрабатывать данные.

ConcurrentDictionary<K, V> использует множество locks. Этот механизм использует полосы, на каждую полосу используются определённые локи. Т.е. для первой полосы используется один лок на несколько ключей, в рамках второй полосы используется другой лок для других ключей. Количество полос  по умолчанию равно количеству ядер CPU.

Для записи тоже использует lock. Для чтения - volatile.

Подходит для сценариев с большой нагрузкой по чтению так как использует полоски, блокировки в которых не вляют друг на друга.

Все структуры concurrent не имеют async ожидания нового элемента и не работают асинхронно.
