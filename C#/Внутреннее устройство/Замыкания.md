
Замыкания это по сути специальные функции, которые хранят состояние (значения локальных переменных) даже после повторного запуска. 
static Func<int> CreateCounter()
{

	int count = 0; // Локальная переменная
	// Возвращаем лямбду, которая "захватывает" count
	return () => ++count;
}
Это пример замыкания. Метод возвращает лямбду и в этом случае count пермещается из стека в кучу и поэтому зпомниет своё значние даже после вызова. По идее переменная должны лежать в стеке, но в этом случае при попытке обратится к count лямбда бы получала бы неверные данные, т.к. к тому времени по этому адресу в стеке лежали бы другие данные и произошла бы ошибка памяти. Для того, чтобы избежать этого компилятор вынужден держать эту переменную в куче а не в стеке.

Своего рода функции с состоянием. Нужны чтобы
-  работал LINQ,
-  иногда нужно просто запомнить состояние без использования объектов
-  создаём одну функцию GreatherThan(int x), в которую можно передать разный x а не писать под каждое условие отдельную функцию

  Копмпилятор генерирует такой класс:
  private class Closure { 
	  public int x; // захваченная переменная 
	  public bool Invoke(int n) => n > x; 
  }
  
-  для использования колбэков, которые помнят значения переменных, которые в него передали, то есть функция захватывает переменные из внешнего контекста

В памяти это выглядит как класс, где переменные - это поля класса, которые расположены в куче поэтому при изменении перменной за пределами замыкания внутри замыкания значения переменных так же меняются.
