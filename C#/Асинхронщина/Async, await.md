Это механизм асинхронного выполнения кода, который даёт возможность НЕ блокировать потоки при вызове долгих и дорогих запросов (как правило запросы к бд, к сети, к файловой системе).

ConfigureAwait - это указание в какой поток возвращаться после выполнения async метода. Если true - то заходим в контекст синхронизации, который выполняет оставшийся код с учётом результата async метода в том же потоке, если false - то в любой поток из пула потоков.

Контекст синхронизации - по сути асбстрактный класс с одним методом, который решает в каком потоке выполнить continuation. У UI контекст синхронизации привязан к UI потоку, в старых версия ASP.Net Framework контекст синхронизации привязан к потому в котром находится HttpContext, XUnit.

Каждый тест XUnit должен выполняться на одном и том же потоке потому что xunit подразумевает, что могут быть данные, которые привязаны к потоку, например, транзакции.

При async/await используется стейт машина. При await НЕ вызывается отдельный поток, происходит вызов к внешней системе  (например запрос к бд) а потомок вызвавший этот await возвращается в пул потоков. Но когда запрос к бд выполнится выполнение должно продолжится с той точки в которой останосилось и все переменные, которые были использованы до вызыва await должны быть доступны и после вызова await. Для этого их нужно где - то сохранить, они сохраняются в памяти стейт - машины. Физически это означает что для каждого метода у которого есть await создаётся ОДНА state машина и все локальные переменные становятся переменными стейт машины. Использование await достаточно дорогая операция с точки зренимя использования памяти так как каждый async метод создаёт state машину что по сути является аллокацией памяти.

В случае с UI если мы вызовем синхронно метод await (используя configureawait(true) ) через .Result,.Wait то тем самым мы заблокируем UI поток, но в то же время await отработает и попытается вернуть результат в тот же самый поток UI но он заблокирован. Вот так и возникнет дедлок.  При этом Configureawait(false) решило бы проблему.

Await внутри [[Monitor, Lock]] мы не можем использовать т.к. lock производит блокировку в потоке и привязан только к нему в том время как await не привязана к потоку.
