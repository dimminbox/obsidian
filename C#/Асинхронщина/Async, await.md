Это механизм асинхронного выполнения кода, который даёт возможность НЕ блокировать потоки при вызове долгих и дорогих запросов (как правило запросы к бд, к сети, к файловой системе).

ConfigureAwait - это указание в какой поток возвращаться после выполнения async метода. Если true - то заходим в контекст синхронизации, который выполняет оставшийся код с учётом результата async метода в том же потоке, если false - то в любой поток из пула потоков.

Контекст синхронизации - по сути эта класс с одним методом, который ставит результаты выполнения async методов в специальную очередь для дальнейшей их обработки. Существует только в UI, старом ASP.Net Framework (там HttpContext привязан к потоку), XUnit.

Каждый тест XUnit должен выполняться на одном и том же потоке потому что xunit подразумевает, что могут быть данные, которые привязаны к потоку, например, транзакции.

При async/await используется стейт машина. При await НЕ вызывается отдельный поток, происходит вызов к внешней системе  (например запрос к бд) а потомк вызвавший этот await возвращается в пул потоков. Но когда запрос к бд выполнится выполнение должно продолжится с той точки в которой останосилось и все переменные, которые были использованы до вызыва await должны быть доступны и после вызова await. Для этого их нужно где - то сохранить, они сохраняются в памяти стейт - машины. Физически это означает что переменные из стека сохраняются в кучу и обратно после await. Поэтому await достаточно дорогая операция с точки зренимя использования памяти поэтому не нужно где не попадя использовать await.

Await внутри [[Monitor, Lock]] мы не можем использовать т.к. lock производит блокировку в потоке и привязан только к нему в том время как await не привязана к потоку.
