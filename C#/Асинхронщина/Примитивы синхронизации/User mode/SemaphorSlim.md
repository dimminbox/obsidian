Это примитив синхронизации, который работает на очередях. Например, первый поток захватил ресурс, второй поток тоже хочет прочитать ресурс, но не может т.к. он заблокирован. Когда первый поток отработал он вызывает Release вручную и это будет следующие на очереди поток на доступ к ресурсу.

`// Разрешаем не более 3 одновременных запросов к внешнему API`
`var semaphore = new SemaphoreSlim(initialCount: 3, maxCount: 3);`

`async Task<string> CallApiAsync(string url)`
`{`
    `await semaphore.WaitAsync(); // занимаем один "слот"`
    `try`
    `{`
        `return await httpClient.GetStringAsync(url);`
    `}`
    `finally`
    `{`
        `semaphore.Release(); // освобождаем слот для следующего ожидающего`
    `}`
`}
// Запускаем 10 задач параллельно, но реально выполняться будут максимум 3 одновременно
var tasks = urls.Select(url => CallApiAsync(url));
await Task.WhenAll(tasks);
`
`

Первый параметр - это количество соотвествующее количество потоков, которые могут сразу войти в критическую секцию без ожиданий. Второй параметр -  это максимальное количество одновременных потоков, которые могут параллельно входить в критичную секцию. 

SemaphorSlim поддерживает async/await.

Работает в рамках одного процесса но может синхронизировать доступ к данным в рамках разных потоков.
