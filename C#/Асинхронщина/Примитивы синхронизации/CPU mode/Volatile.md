Примитив, которые работает на уровне CPU и гарантирует строго последовательное выполнение инструкций в том порядке, в котором они записаны в коде. Иногда CPU в рамках оптимизации выполняет операции в другом порядке когда они идут последовательно друг за другом, например:

`private int _data;`
`private volatile bool _ready;`

`void Producer()`
`{`
    `_data = 42;           // 1`
    `_ready = true;        // 2: volatile-запись, 1 не уйдёт ниже неё`
`}`

`void Consumer()`
`{`
    `if (_ready)           // volatile-чтение`
        `Console.WriteLine(_data);   // 2 не уйдёт выше чтения, увидим 42, а не 0`
`}`

Разные потоки могут выполнять операции в разном порядке и получается, что значения переменных могут меняться не так как заложено в коде. Volatile запрещает такую оптимизацию.

Также он гарантирует, что значение будет прочитано из памяти а не из кеша ядра процессора. Он просто читает переменную из памяти, не блокируя шину памяти. Поэтому он не подходит для задач где нужна атомарность изменения переменной.

Если переменная типа bool, то volatile подходит так как у нас отсуствует операция ADD, т.е. мы просто записывает значение не учитывая предыдущее значение, которое может изменить другой поток, т.е. volatile - это не лок на переменную.

Этот примитив подходит для задач где один поток пишет а другие читают. В этом случае читающие потоки гарантированно увидят актуальное значение переменной.

Есть и оператор Volatile, который накладывает ограничение volatile только на момент обращения к переменной, т.е. переменная может быть не помечена как volatile.

`Volatile.Read(ref _value);`
`Volatile.Write(ref _value, 1);`
