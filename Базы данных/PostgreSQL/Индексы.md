
При работе с индексами Postgres всего решает какой процент строк возвратит сам запрос. Это основывается на собранной и обновляемой заранее самой БД статистике. Перед выполнением запроса Postgres сравнивает варинты выполнения запроса, основанной на статистике. Варинты могут быть как с использованием индексов, так и без них. Он смотрит на стоимости выполнения запроса, который возаращают разные варианты.  Если вариант с использованием индекса возвращает меньшую стоимость, то применение индекса выгодно и он будет исполнять запрос имеено с индексом.  Если же нет, то дешевле использовать вариант без индекса. 

#### Btree - индексы 

Это основной тип индексов, который представляет из себя древовидную структуру. Индексы могут содержать сразу несколько колонок, но подрядок колонок важен, потому что поиск по индексу работает слева направо.  Работает следующим образом: допустим, что нам нужно найти все записи где cost < 3000. Идёт от корневого узла, 3000 меньше корневого узла? - идёт налево, иначе направо и так дальше. Когда дошли до нужнго узла, то берём указатель, которые хранится в этом узле и читаем соответствющую строку из таблицы.


#### Include - индексы 

Это индексы которые хранят данные уже в себе, т.е. нет необходимости брать данные из таблицы по индексую Данные в include хранятся в индексе но не участвуют с процессе поиска или сортировки.

###### Partial индексы

Индексы в Postgres которые строятся только на данных,удовлетворяющих заданным условиям.

###### Gin индекс

Предназначен для хранения значений в полях, которые представляют из себя не отдельные значения а целые структуры (json). Он хранит соотвествие значений полей этих структур и строк.
