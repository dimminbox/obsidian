
Это паттерн, который гарантирует создание всего одного объекта заданного типа в рантайме.

Можно реализовать как класс, который бы создавал в статической переменной  с [[Volatile]] объект заданного класса с использованием lock.

Также он может быть реализован через Lazy<T> что более правильно:
public class Singleton 
{ 
	private static readonly Lazy<Singleton> _lazy = new( () => new Singleton());
	public static Singleton Instance => _lazy.Value;
	private Singleton() { }
}

Но лучше использовать Singleton через DI потому что его можно замокать.
Сам паттерн имеет ряд недостатков:

- нарушает принцип единственной отвественности, т.к. управляет бизнесс - логикой и своим временем жизни
- нарушется принцип dependency inversion т.к. заставляет зависеть классы от себя а не от абстракции
- любой код может изменить его состояние, сложно отследить кто и когда изменил
- один экземпляр на программу поэтому тесты могут влиять друг на друга через общее состояние
- живёт вечно, память не освобождается. Если он накапливает данные, то потребление памяти растёт
- если он захватывает AddScoped, AddTransient зависимости то всё равно они будут одни навсегда т.к. синглтон один даже не смотря на то, что объявлены для каждого запроса и каждого вызова. Это называется Captive Dependency.
- не thread-safe
