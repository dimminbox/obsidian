
Паттерн для обеспечения атомарности операций, которые выполняются в рамках разных сервисов, которые, например, имеют свои хранилища. Одной из реализацией паттерна saga может быть оркестратор, который координирует поведение сервисов на основе событий с помощью шагов.

Например, при обработке заказа цепочка слеудющая: сервис заказов сохраняет заказ, сервис оплаты проводит оплату, сервис склада резервирует товар. Что если сервис склада упадёт? Без использования saga - оркестратора система разбалансирована. Если такое произойдёт, то Saga пошлёт сообщения в сервисы payments, orders, о возврате платежа и отмене заказа соответственно. Оркестратор должен быть отказоустойчивым.

Также паттерн Saga можно реализовать без центрального оркестратора просто на базе сообщений. Допустимо использовать обмен сообщениями если сервисов в цепочке не много, до 5 штук, иначе будет хаос.
