Набор принципов с помощью которых пишется чистый, масштабированный, поддерживаемый код.

-  Single Responsibility Principal (SRP) - принцип который означает, что у класса должна быть единственная причина, по которой его можно изменить. В соответствии с этим принципом классы должны отвечать только за одну вещь (часть бизнесс логики).
  
-  Open/Closed Principal (OCP) - принцип открытия/закрытия, который гласит, что класс должен быть закрыт для изменений но открыт для расширения, которое может быть осуществлено через: наследование, интерфейсы, композицию, паттерны.
  
-  Liskov Substitution Principal (LSP) - принцип, который гласит, что объект подкласса должен быть полностью заменяем объектом базового класса без нарушения работы программы, т.е. он не должен менять смысл наследуемых методов, усидивать предусловия (какая - то новая валидация) или ослаблять постусловия (), вообщем не должен менять ожидаемое поведение. Для добавления логики в класс - потомок используется расширение класса с помощью добавления новых методов и наследования.
  
- Interface Segregation Principal (ISP) - принцип в соотвествии с которым интерфейсы не должны быть жирными, т.е. лучше дробить интерфейсы на более мелкие , чем использовать один. Таким обрзом он избавляет класс от реализации  не нужным методов. По сути ISP - SRP но только для интерфейсов.
  
-  Dependency Inversion Principal (DIP) - принцип, который требует чтобы классы зависели от абстракций а не от реализаций, таким образом система получается менее связанная и вероятность нарушения работы программы при изменениях класса уменьшается нежели если использовать прямые зависимости между классами.
