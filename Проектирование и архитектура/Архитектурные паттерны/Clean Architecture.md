Это архитектурный паттерн который позволяет делать приложения более чистыми, соблюдая принципы SOLID, а именно разбивая приложения на слои для соблюдения в частности принципа Inversion Principal (обратные зависимости).

В центре приложения находится слой домен с бизнесс - логикой (aggregates, value objects, entities, domain events), слоем выше - application (cqrs, интерфейсы сервисов, dto, маппинг, валидация), ещё выше - инфраструктура (реализация сервисов, репозитории, миграции, внешние апи и прочее), слой presentation (контроллеры, миддлвары) зависит только от application.

Value отличается от Entity потому что он иммутабельный, не содержит идентификатора и определяется лишь своими свойствами. Entity же имеет идентификатор, две сущности с разными идентификаторами и одинаковыми свойствами - это разные сущности.

Агрегат - группа объектов, которые изменяются вместе как единое целое, гарантируют инвариантность бизнесс - правил внутри себя, aggregate root является точкой входа.

Child Entity - объект, который не может быть самостоятельным в контексте, например товар в заказе.
