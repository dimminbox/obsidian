Rest (Representation State Transfer) - это архитектурный стиль, описывающий как должен работать API, которое содержит ряд правил и ограничений.

REST содержит список методов, которые может использовать API:
 -  GET - это идемпотентный метод для поиска информации
 -  HEAD тоже самое что GET только возвращает только загловки
 - OPTIONS - идемпотентный метод, который запрашивает у сервера какие вообще методы поддерживаются. ИСпользуется в CORS когда клиент с его домена присылает запрос и хочет убедится что методы вообще поддерживаются.
 -  POST - неиденпотентный метод, который используется для операций создания объектов, т.е. создание одно и того же объекта приведёт к нескольким созданным объектам в хранилище
 -  PUT - идемпотетный метод используется для обновлении информации целиком о сущности
 -  DELETE - идемпотентный метод используется для удаления информации
 -  PATCH обновляет только указанные поля, может быть и идемпотентным при обновлении статуса или неидемпотентным, например, при увеличении суммы на 100.
   
Также он сожержит стандартные коды ответов: 
-  20х - успешные ответы
-  30х - редиректы, 301 - временный, 302 - постоянный
-  40х - ошибки клиента, например, 401 - нужна аутентификация, 403 - доступ запрещён
-  50х - ошибки сервера

REST предполагает ряд преимуществ, которые гарантируют корректную обработку запросов
 - Единый интерфейс (/orders)
 - Кешируемость. Сервер указывает можно ли кеширвоать ответ через заголовок cache - control
 - Stateless, сервер не хранит состояние между запросами, каждый запрос самодостаточен и не зависит от состояния.
 - Клиент не знает с кем общается напрямую, у него просто есть API. Это может быть api gateway, load balancer и т.д, также внутри может быть слоистая архитектура,
